# Code review, October 2026

An internal review of the whole repository for maintainability, elegance (spaghetti, workarounds such as sleeps that
paper over races) and how easy it is for a new contributor to find their way. Baseline before any fix: `make check`
green (Python 177 tests, plugin, launcher-core, Swift 87, pplx 21).

Each finding has an id, a size (S/M/L) and a status: **fixed** (with the commit), **partly**, **open** (worth doing, not
done here) or **no** (looked at and judged fine). Open items are the to-do list this review leaves behind. After the
fixes: `make check` green (Python 188, plugin 185, launcher-core 46, Swift 88, pplx 21); `make app-selftest` green in 6
of 7 runs (see 533b50a).

**Second pass (same day):** the MIT license and the big refactors (P2, P5, T2, T4, W1, W6) are done. **Biggest open items now:** P4 (stale-index warning: needs a design choice), P6 (CLI commands calling each other through fake argparse objects), P9 (watcher holds the lock through the quiet wait), T3/T5/T6 (dead `embedQuery` path, plugin eval script, three copies of rank fusion), C3 (spec-id test names).

## Summary

The project is in better shape than most personal codebases: the docs are unusually good (AGENTS.md, DEVELOPMENT.md,
specs with numbered tests), tests inject clocks instead of sleeping, and the rules (atomic index writes, one ranking
implementation, no personal data) are written down and mostly enforced. The debts cluster in four places:

1. **Install and launchd plumbing** (shell): three of four committed plists hold the owner's absolute paths, the watcher
   plist exists twice (file and heredoc), `bootout` → `bootstrap` races in `setup-search.sh` although `install-service.sh`
   already documents and handles it, and `./setup-search.sh index --full` silently drops `--full`.
2. **The two Python index builders** are 400 and 240 line functions that copy each other; helpers shared by everything
   live in `searchindex.py`, which causes a circular import; defaults are repeated in up to 8 places.
3. **The three TypeScript query UIs** (modal, `@@`, related panel) each implement debounce + stale-result handling their
   own way; the modal's copy has the bug the `@@` copy already fixed.
4. **`AppModel.swift`** does a dozen jobs in the untested app target; its debug modes and the self-test sleep for fixed
   times instead of waiting for the event they need, and several test helpers poll and time out silently.

Sleeps that are **legitimate** and stay: capped backoffs in `embed.py`, `pplx.py`, `llm.py` (honours `Retry-After`);
`flock` polling in `named_lock` (no timeout in Python's API); `pplxd` waiting for the llama-server it started; the
watcher's quiet-window wait (injected clock); the app's 60 s safety poll, toasts, debounces (already behind `Sleeper`
/`Scheduler`), the clipboard restore delay (no signal exists); `install-service.sh`'s bounded wait for `bootout`; all
plugin timers (real debounces on an injectable clock).
